# Quickstart: 第1弾 メモ・復習・クエスト

第1弾ができあがったことを確かめるための手順。実装の中身は tasks.md と実装の段階で決める。

## 必要なもの

- Node.js 24 と npm 11（このPCでは確認済み）
- claude.ai のアカウント（公開後の確認用）。Googleカレンダーのコネクタがつながっていること

## 準備とテスト

```bash
npm install
```

```bash
npm test
```

期待する結果: `tests/domain/` のテストがすべて通る。特に次の場面を確かめるテストがあること。

| テストの場面 | 期待する結果 |
|---|---|
| 10/6 に登録したメモ | 10/7 に出題される |
| 段階0で「覚えてた」→ 段階1 | 3日後に出題 |
| 段階4（30日）で「覚えてた」 | 段階5、60日後に出題、「討伐済み」 |
| どの段階でも「忘れた」 | 段階0、翌日に出題 |
| 10/7 午前3:59 の学習日 | 10/6 |
| 出題日が来たメモが70件 | 今日の復習は古い順に50件 |
| 予定「【仮】面接日程候補」 | 就活の日と判定 |
| 今週の就活の日が2日、1日の新しいメモ目標5件 | 就活のない日の目標は 5 + 切り上げ(10 ÷ 5) = 7件 |
| 10:00〜13:00 が空いている | 「10:00〜13:00（3時間）: 過去問道場で20問＋復習」と提案 |
| 累計経験値 500 | レベル5「用語ハンター」 |
| 「用語: 説明」の形の10行を貼り付け | 10件のメモの候補 |

## 開発用の画面で確かめる

```bash
npm run dev
```

ブラウザで表示されるアドレスを開く。`window.claude` がないので、開発用のつなぎ口で動き、
画面に「サンプル」と表示される。ブラウザの開発者ツールで幅を375pxにし、ライトとダークの両方で次を確かめる。

1. ホームで用語と説明を入れて保存できる（10秒以内に操作が終わる）
2. 同じ用語をもう一度入れると、既存のメモが知らされる
3. 開発用の「日付を進める」操作で翌日にすると、そのメモが復習に出る
4. 「覚えてた」「あやしい」「忘れた」で次の出題日が変わる
5. ダミーの予定に「面接」がある日は、デイリークエストが「復習だけ」になり、理由が表示される
6. 図鑑で検索・編集・削除ができ、削除の前にページ内で確認される
7. ワールドマップで、メモを増やした地方の状態が変わる
8. 横スクロールが出ない

## 公開して確かめる

```bash
npm run build:artifact
```

`artifact/index.html` ができたら、Claude Code に「artifact/index.html を公開して」と頼む
（research.md R18 のケーパビリティを宣言して公開する）。公開したページを claude.ai で開き、次を確かめる。

| 確認 | 期待する結果 | 対応 |
|---|---|---|
| PCでメモを登録し、スマホで開く | 同じメモが見える | SC-007 |
| アプリを開く | 3秒以内に今日やることが表示される | SC-002 |
| 機内モードでメモを保存し、通信を戻して開き直す | メモが保存されている | FR-005 |
| 「AIチェック」を押す | 判定・ひっかけポイント・問題が表示され、「AIが作成」の印が付く | ストーリー4 |
| AIの利用を許可しない | AIのボタンが隠れ、メモと復習はそのまま使える | FR-021 |
| 設定で就活のカレンダーを選ぶ | 面接・面談のある日のクエストが軽くなる | ストーリー5、SC-004 |
| カレンダーの利用を許可しない | 通常のノルマで表示され、小さく理由が出る | ストーリー5 |

公開後、Claude Code が保存されたデータを1回読み出し、書き込みが本人の非公開領域に入っていることを確かめる。
